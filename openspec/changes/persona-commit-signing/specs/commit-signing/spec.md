# Spec Delta

## Purpose

Defines how Dark Factory signs every commit a run makes with its persona's signing key, without the key ever entering the sandbox: key generation, storage and rotation, the signing service and its guards, and how the sandbox requests signatures.

## ADDED Requirements

### Requirement: One signing key per persona
Every persona SHALL have an Ed25519 SSH signing key, generated by the control plane when the persona is saved, or before its first run if it has none. The private key SHALL be stored only in a Kubernetes Secret in the instance namespace and held only in the control plane's memory. It SHALL never be written to the database, a log or an audit entry, and never sent to a sandbox or a gateway.

#### Scenario: New persona
- **WHEN** a board member creates persona `linus`
- **THEN** a Secret holding an Ed25519 private key for `linus` exists, and the database holds only its public key and fingerprint

#### Scenario: Persona from before the upgrade
- **WHEN** persona `ada` has no key and a run of `ada` is created
- **THEN** a key for `ada` is generated before the run's sandbox is provisioned

#### Scenario: Key not in the sandbox
- **WHEN** the agent searches the sandbox filesystem and environment for the private key
- **THEN** it doesn't find it

### Requirement: Public key on the persona page
The persona page SHALL show the persona's public signing key in OpenSSH format, its SHA-256 fingerprint and the commit email, each with a copy action, and SHALL link to the how-to for registering them on the forge's bot account.

#### Scenario: Registering on the forge
- **WHEN** a board member opens persona `linus`
- **THEN** they see `ssh-ed25519 AAAA…`, `SHA256:…` and `linus@example.org`, each copyable, and a link to the forge how-to

### Requirement: Key rotation
A board member SHALL be able to rotate a persona's signing key. Rotation SHALL replace the key in the Secret and the public key in the database, SHALL write an audit entry `persona.signing_key.rotate` with the old and new fingerprint, and SHALL apply to every later signature and push check. When the persona has active runs, the confirmation SHALL name how many and say that their unpushed commits must be re-signed.

#### Scenario: Rotate
- **WHEN** a board member rotates the key of `linus`
- **THEN** the persona page shows a new fingerprint, and an audit entry with both fingerprints exists

#### Scenario: Rotate with active runs
- **WHEN** `linus` has 2 active runs and a board member chooses rotate
- **THEN** the confirmation says that 2 runs are active and that their unpushed commits must be re-signed

#### Scenario: Rotation failed after the Secret was replaced
- **WHEN** a rotation of `linus` replaced the key in the Secret but failed to store the new public key, and a run of `linus` then commits
- **THEN** the database is updated to the Secret's public key with an audit entry `persona.signing_key.reconcile`, and the commit is signed with that key

### Requirement: Commits are signed at commit time
The runtime SHALL configure Git so that every commit made in the workspace is signed with an SSH signature produced by the signing service, by the harness and by the runtime alike, except WIP snapshot commits. If no signature can be obtained, the commit SHALL fail with an error that names the reason.

#### Scenario: Harness commit
- **WHEN** the agent of a run with persona `linus` runs `git commit`
- **THEN** the commit carries an SSH signature that verifies against `linus`'s public key with namespace `git`

#### Scenario: Control plane unreachable
- **WHEN** the agent runs `git commit` while the runtime is disconnected from the control plane for more than 10 seconds
- **THEN** `git commit` fails with a message that signing is unavailable, and no commit is created

#### Scenario: WIP snapshot
- **WHEN** the runtime creates a WIP snapshot commit
- **THEN** the commit has no signature

### Requirement: Signing guards
The signing service SHALL sign only a payload of at most 1 MiB that parses as a Git commit object whose author and committer name and email equal the run's persona identity, for a run that is active. It SHALL refuse any other payload, with a reason, and sign nothing.

#### Scenario: Commit as another identity
- **WHEN** a run of `linus` requests a signature for a commit authored by `ada@example.org`
- **THEN** the request is refused with "author does not match the persona identity" and `git commit` fails

#### Scenario: Not a commit
- **WHEN** a run requests a signature for a tag object or arbitrary bytes
- **THEN** the request is refused and nothing is signed

#### Scenario: Ended run
- **WHEN** a sign request arrives for a run that has ended
- **THEN** it is refused

### Requirement: Signatures are audited
The control plane SHALL write an audit entry `commit.sign` for every signature it produces, with the agent actor (persona, run, task), the key fingerprint and the commit's tree id. It SHALL write an audit entry `commit.sign_refused` for every refusal, with the reason.

#### Scenario: Signed commit
- **WHEN** the agent of `DF-7` (persona `linus`) commits
- **THEN** an audit entry `commit.sign` with persona `linus`, the run and task `DF-7`, `linus`'s fingerprint and the commit's tree id exists

#### Scenario: Refused request
- **WHEN** a sign request is refused because the author does not match
- **THEN** an audit entry `commit.sign_refused` with the reason exists
