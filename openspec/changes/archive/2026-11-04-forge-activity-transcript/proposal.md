# Proposal

## Why

A board member following a task cannot see in the transcript when the agent's work reached the forge: when commits were pushed to the task branch, when a push was rejected, when the draft PR was opened or marked ready. The details column shows the PR link, but not when it appeared relative to the agent's work. Decided in [ADR-0046](../../../docs/adr/0046-forge-activity-in-the-transcript.md).

## What Changes

- New transcript event kind `ForgeActivity` in `darkfactory.transcript.v1` (additive), with the variants `BranchPushed`, `PullRequestOpened` and `PullRequestReady`.
- The control plane writes forge activity into the run's transcript:
  - a final push record from the gateway for the run's task branch (`accepted`, `rejected`, `upstream-failed`), in the same transaction as the push record;
  - a PR recorded for the task (opened or found), in the same transaction as recording it;
  - a PR marked ready for review after a completed run, once the forge accepted the update.
- `transcript_events` accepts control-plane events: `seq` becomes nullable and a `source_key` column identifies a control-plane event, exactly one of the two set, unique per run. Retries write nothing new.
- The transcript shows forge activity as one accent-tinted row per event with its own icon (commit, draft PR, PR); rejected pushes are tinted as errors; PR rows link to the PR.
- Forge activity is display-only; it is never sent to the agent.

Out of scope:
- Forge events after a run has ended (PR merged or closed, review submitted): backlog in `product/iterations/roadmap.md` ("Forge activity outside runs").
- Commit and compare links on push rows: backlog in `product/iterations/roadmap.md` ("Commit links in forge activity").
- WIP branch pushes as forge activity: rejected (runtime housekeeping).
- The runtime's `PushReport` as source for push rows: rejected (reported from the untrusted sandbox).

## Capabilities

### New Capabilities
- `forge-activity`: which forge-side effects of a task's work the control plane records in the transcript, from which trusted source, with what content, and exactly once.

### Modified Capabilities
- `transcript-storage`: transcript events can be written by the control plane, identified by a source key instead of a runtime sequence number; order and live notification apply to them as well.
- `task-ui`: the transcript renders forge activity rows.

## Impact

- `contract/proto/darkfactory/transcript/v1/transcript.proto` (new message, new `oneof` field 19), `df-proto` regenerated by the build.
- `df-db`: migration on `transcript_events`; `git_pushes::record_push` writes the push event; a shared insert for control-plane events that publishes `transcript_event`; `.sqlx/` metadata.
- `df-agent-channel`: `pr.rs` writes PR events; `transcript.rs` ignores the new kind for anything agent-facing.
- `df-web`: transcript folder and renderer, two new Lucide icons, `docs/design-system.md`.
- Docs: ADR-0046 (written), `product/GLOSSARY.md` (written), `contract/README.md`.
