## Context

The traffic page (`egress/log/page.rs`) is header, filter bar and the `#split` grid (graph, divider, events) in normal page flow, so the page scrolls as a whole. The graph is server-rendered HTML nodes plus an SVG for the edges, as tall as its nodes need (up to ~2,000 px at the caps of 12 sandboxes and 30 destinations), and is morphed on live updates (`style` is in `morphIgnore`). Flow events live in `FlowLog` per gateway pod (count limit `gateway.bufferSize`) and, per relay session, in the control plane's `Merged` buffer (constant `BUFFER_EVENTS`). `Merged` is kept in time order (`partition_point` on insert); `FlowLog` is in record order, which can differ slightly from `time` order because the timestamp is taken before the lock. `GatewayConfig` is shared by the gateway and the control plane. In the shell, the main area has only `min-h-dvh`, and `#split` sits inside `#traffic` (the filter form's swap target), so neither is a flex child of a box with a definite height. After a token refresh the SSE stream reconnects and its first message, the new backlog, replaces the table body and the graph.

## Goals / Non-Goals

**Goals:** header and filters always visible, graph and table scroll independently, events older than an hour leave the buffers.
**Non-Goals:** zoom (later), aging rows and graph edges out of an open page, a timer that evicts without traffic.

## Decisions

1. **Viewport-high column with CSS only.** Every box from the page root down to the panels needs a definite height or must be a shrinking flex child. The page root becomes `md:flex md:h-[calc(100dvh-4rem)] md:flex-col`: the viewport minus the main area's `md:py-8` (`layout.rs`), so it does not depend on the shell's `min-h-dvh`. Below `md` (bottom bar, stacked panels) the page keeps its normal flow. Header and filter bar keep their natural height (`shrink-0`). `#traffic` becomes `flex min-h-0 flex-1 flex-col`, and `#split` inside it gets `min-h-0 flex-1` and `items-stretch` instead of `items-start`. `#traffic` keeps its id and stays the swap target. Each `section` is a flex column whose body (`#graph` wrapper, table wrapper) is `min-h-0 flex-1 overflow-auto`. The table header gets `sticky top-0` with the panel background. The divider stretches to the full height already (`h-full`).
2. **Moving the graph = native scroll plus a drag.** The graph already fits the panel width, so it overflows only vertically; the scroll container is enough to reach every node. A pointer drag on the graph background (not on node cards, so text stays selectable) changes `scrollTop`/`scrollLeft`, implemented in the existing Alpine state next to the divider drag (`pointerdown`/`move`/`up`, pointer capture, `cursor-grab`). The scroll position survives morphs because the scroll container sits outside `#graph`.
3. **Age eviction is lazy and does not rely on order.** One pure function `expired(event, cutoff, open_flows)` decides: an event is expired when its `time` is before `now - max_age`, except an `opened` event whose flow has no `closed` event yet. The open flows are not tracked in a running set: each read and each prune computes them from the buffer (an `opened` event of a pod and flow id with no `closed` event in the buffer, flow id 0 never counts), before any event is dropped, so a closed flow's old `opened` event cannot look open once its `closed` event aged out. A tunnel open for longer than an hour still shows on a newly loaded page. `subscribe` filters the backlog with the function, so an expired event is never handed out, whatever its position. `record` / `insert` run `retain` with it at most once a minute, which keeps memory bounded without an O(n) pass per event; the count limit still drops the oldest event first, pinned or not. No timer task. The cut-off and the prune time are arguments of the internal functions, so tests need no clock. The setting is clamped to at least one second in code, as in the Helm schema.
4. **One setting for both buffers.** `gateway.bufferMaxAgeSeconds` (default 3600, minimum 1) in `GatewayConfig`; the gateway passes it to `FlowLog`, the control plane to the relay. `Merged` keeps its count constant.
5. **Open pages age out only on a new backlog.** The page does not age rows itself. It keeps what it received until it gets a new backlog: on *Resume*, on a reload, and on the automatic reconnect after a token refresh, which replaces rows, graph and counts with the current last hour. So older rows can disappear without user action, at the latest at the next token refresh. Accepted as is and documented in the reference; keeping rows across reconnects would need client-side merging for no requested benefit.

## Risks / Trade-offs

- Events whose `time` is skewed into the future (pod clock drift) stay a bit longer; acceptable for a live view.
- The sticky table header needs an opaque background, otherwise rows show through in dark mode; use the panel token.
