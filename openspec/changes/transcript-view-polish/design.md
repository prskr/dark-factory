## Context

The transcript is a plain `overflow-y-auto` div (`selected_columns`); items are appended by SSE partials (`beforeend` into `#transcript`, `outerMorph` for growing items). Opening a task swaps `#ws-detail` through htmx. The queued stack is `#pending` (`pending_region`), the runs are `#runs` (`runs_region`), both morphed live. htmx is configured to keep `open` on morph (`HTMX_CONFIG`). The page has no inline `<script>`; behavior comes from Alpine attributes.

## Goals / Non-Goals

**Goals:** items 1 to 3 of the request, following the PenPot board "Desktop · many queued messages".
**Non-Goals:** a "jump to latest" button, virtualized transcript, sandbox cooldown, manual task status.

## Decisions

1. **Scroll follow in Alpine, no new script.** The transcript container gets `x-data="{ pinned: true }"`, `x-init` scrolls to the bottom and starts a `MutationObserver` (childList, subtree, characterData) that scrolls to the bottom when `pinned`, and `x-on:scroll` sets `pinned` to "within 48 px of the bottom". A swapped-in container re-runs `x-init`, which covers opening another task. Alternative: htmx events per partial; rejected, they do not fire for in-place text growth and need per-partial logic.
2. **Queued list: a wrapper inside `#pending`, compact rows as in the board.** The board's "queued item" is a single 36 px row (text cut to one line, time and the edit/remove buttons inline), not today's card with up to three text lines and the time below it. The rows switch to that layout, always, so the list does not change shape when the fourth message arrives: the row height equals the existing icon button (`ICON_BUTTON_CLASS`: `size-11 lg:size-9`) with no vertical padding, so `h-11 lg:h-9` holds the buttons and keeps the 44 px touch target below `lg`; text `truncate` with the full text in `title` and in the edit form, time and buttons inline. Header line plus `div` with `max-h` of three rows plus two 4 px gaps, written with the same size classes as the rows (`max-h-[calc(3*2.75rem+2*0.25rem)] lg:max-h-[calc(3*2.25rem+2*0.25rem)]`) so they cannot drift apart, and `overflow-y-auto`. `#pending` keeps its id and the morph keeps the node, so the scroll position of the list survives updates. The persona name is passed to `message_area` / `pending_region` from `TaskDetail.persona_name`.
3. **Runs newest first in the query.** `list_runs` orders `number DESC`; its only consumer is the details column. The transcript dividers are independent of it.
4. **Runs collapse with native `<details>`, closed by default.** `runs_region` renders the existing `section` look with `<details>`/`<summary>` ("Runs" + count) without `open`. `open` is in `morphIgnore`, so a live update neither closes a list the reader opened nor opens a closed one. No persistence across reloads (unlike the details column): every load starts closed. Alternative: Alpine + `localStorage`; rejected as more code for no requested benefit.
5. **Design stays the master.** The collapsed runs list has no board yet. "Desktop · runs collapsed" (page "Desktop") shows the closed default; the runs header of "Desktop · light" gets the chevron (down) and the count for the open state. Both are drawn before the markup is finished and added to the mapping table in `docs/design-workflow.md`.

6. **Runs scroll inside their section.** From `md` the details body no longer scrolls as a whole: it is a flex column with `min-h-0`, the sections above Runs keep their height (`shrink-0`), and `#runs` is `min-h-0 flex-1`. The `<details>` fills it, its summary (chevron, "Runs", count) stays fixed and the `<ul>` is the `overflow-y-auto` element. Collapsing the details leaves only the summary. Below `md` (phone sheet) the whole body keeps scrolling as today and Runs flows at the end.
7. **The upper block cannot starve the runs.** The runs area keeps a minimum height of about two run cards. The Description text is cut after three lines (`line-clamp-3`) with the full text in `title`, so the block above Runs stays short; if it is still taller than the column, the upper block scrolls rather than the runs area shrinking below the minimum.
8. **Design.** PenPot board "Desktop · many runs" (page "Desktop"): Runs open with eight runs, fixed header, scrolling list. Added to the mapping table in `docs/design-workflow.md` and the runs bullet in `docs/design-system.md`.

9. **Tool-call row.** The summary reads: Lucide `wrench` (`Icon::Wrench`, muted, decorative) · title · kind · status · `ChevronDown` at the end. The icon names what the row is; the trailing chevron is the affordance and lines up in one column, so the titles start at the same x on every row. It turns 180° when the row is open (`group` on the `<details>`, `group-open:rotate-180`). The row keeps its `ml-11` indent. An emoji was rejected: it ignores the theme tokens and depends on the emoji font.
10. **Separators in CSS.** Every tool row has `border-t` and `border-b` in the `line` token; a tool row directly after another one drops its `border-t` (sibling rule in `input.css`, as for the avatar grouping), so consecutive calls share one line and live appends regroup without re-rendering. Thoughts and plans are no tool rows and get no line.
11. **Design first.** The tool rows of "Desktop · light" and the other Desktop boards move the chevron from the front to the end and get the wrench and the lines.

12. **No turn-end item.** The `TurnEnded` event still completes the turn's agent messages (rendered as Markdown); it adds no item. `components::transcript::turn_end`, `ItemKind::TurnEnd` and their snapshots go. The run divider separates runs, the run card carries the model and its usage. With several turns in one run the user's message is the boundary.
13. **Run anchors.** The run number in `run_card` becomes `<a href="#run-N">`, the target is the existing divider id (`run-{number}`, `transcript/mod.rs`). The browser scrolls the transcript container; the scroll handler leaves the follow mode, so new items do not pull the reader back. Where the details panel overlays the transcript (below 1280 px) the click closes it. Plain anchors, no script, no history handling. A run without a divider yet makes the link a no-op.
14. **Token table.** Per model two rows: the model name on its own line (`truncate`, full name in `title`), below it the numbers in a three-column grid under the `in` / `out` / `cache` header, right-aligned with a column gap. Counts are compact: below 1,000 exact, 1,000 to 9,999 one decimal and `k` (`9.4k`), 10,000 to 999,999 whole `k` (`182k`), from 1,000,000 `M` with one decimal (`1.2M`), whole `M` from 10 M. The exact value is the `title`; the cache cell reads `read / write`. A horizontally scrolling table was rejected: it hides data.
15. **Design.** The run cards of the Desktop boards get the two-row model layout and the run number as a link (`accent-text`, underline on hover); turn-end lines, if drawn, go.

## Risks / Trade-offs

- A `MutationObserver` on a long transcript fires per appended node; the callback only sets `scrollTop`, which is cheap. Batches arrive at most every `COALESCE` while streaming.
- Reversing the runs order is visible to anything that reads `list_runs` by position; the only caller and the db test are updated.
- A flex column with `min-h-0` needs every ancestor up to `ws-details` to be a bounded flex item. The browser check at 1440 and 1280 px covers this.
