## Decisions the specs don't carry

- Run view: the call records sit inside each run's card in the details column, as a section "Tool calls (MCP)" with the record count after the usage lines; no section when the run has no records.
- One record per call, oldest first, two lines: (1) the tool name in mono (`<server>__<tool>`; a failed list shows as `<server> · tools/list`) with the outcome badge right-aligned; (2) `HH:MM · <duration> · <request size> → <response size>` in `text-muted`, `–` for a missing size.
- Outcome badges (`Tone`): `ok` completed, `rejected` / `upstream-error` / `too-large` failed, `timeout` / `tool-error` limited, `cancelled` queued. The badge shows the outcome as stored (`ok`, `tool-error`, …).
- Settings nav: "MCP servers" after "Model providers", icon `Icon::Wrench`.
- List: like Model providers (two-line rows). Columns "Name" and "Projects" (enabled project keys, comma-separated, or "no project" in `text-muted`). Line 1: the name, then a `Tone::Queued` badge "Private network" when on. Line 2, separated by " · ": the URL as entered (query included), the scheme (`<name> header`, `Authorization: Bearer`, `<name> query parameter`), the credential `name (secret/key)` in mono. Trash icon per row (`hx-confirm` "Delete MCP server <name>?").
- Delete refused: the existing `bg-danger-soft` alert above the list (as `providers.rs` `region`), text "MCP server <name> is enabled for <keys>; disable it there first." No new board.
- Form: a modal like New model provider, one column without tabs, in this order: Name (half width); URL (full width, mono); Credential reference | Credential scheme (select: "Bearer", "Header", "Query parameter"); the write-tools warning; the scheme's fields; "Private network" checkbox with help. Buttons "Cancel" and "Create MCP server" ("Save" when editing; title "Edit MCP server").
- Help texts: Name "Lowercase letters, digits and single hyphens, starting with a letter, at most 20 characters. Agents see the tools as <name>__<tool>. The name can't be changed later."; URL "MCP Streamable HTTP endpoint; path and query parameters are kept. The URL is not secret: it is stored and shown here. A token belongs into the credential reference, not into the URL."; Private network "Skips the check that refuses private, link-local and loopback addresses. Only for servers on internal names in DNS you control: it also allows localhost and the gateway's own ports."
- Scheme fields: Bearer: none, help under the scheme select "Sent as Authorization: Bearer <value>.". Header: "Header name" (mono, help "Any header except hop-by-hop headers, Host, Content-Length, Content-Type, Accept, Mcp-Session-Id and Mcp-Protocol-Version.") | "Value" split input (prefix placeholder "Prefix", example token; help "Optional prefix, then the secret. Sent as <name>: <prefix><value>. The token is an example."). Query parameter: "Parameter name" (help "Added after the URL's own parameters, URL-encoded. Must not already be in the URL (compared after percent-decoding).") | "Sent to": read-only `bg-sunk` mono preview of the URL ending `&<name>=<value>` (`?` when the URL has no query), help "The upstream and proxies in front of it may log full URLs, query included. Prefer Bearer or Header when the server supports them."
- Write-tools warning: `bg-status-limited-bg text-status-limited-fg`, rounded box, full width, under the credential row. Title (600) "Agents get every tool of this server, including tools that write"; body "In tasks and chats, agents see every tool the server offers, with its unreviewed description. Writes bypass the Git proxy's push checks and the factory's approvals. The credential's scope is the effective permission: use a read-only token where possible, and never a forge token with write access." Shown when creating and editing.
- Edit: the name is a read-only field (`bg-sunk`), help "The name can't be changed: it is part of every tool name agents see (<name>__<tool>)."
- Errors: the existing field error style (red border, red 12 px text under the field). Name: "Use lowercase letters, digits and single hyphens: start with a letter, end with a letter or digit, at most 20 characters." Credential reference: "credential `<ref>` is the forge credential of project <KEY>" (or "… is the credential of model provider <name>").
- "Private network" is a checkbox (form style), not a switch.
- Project tab "MCP servers": last tab, after "Integrations" (`Editing::AsAdmin` only), `saves: false` like Egress, so the header has no "Save project". Contents: group heading "MCP servers", intro "Runs of this project, chats included, get every tool of the servers checked here, with each server's shared credential. Nothing is enabled by default. Changes apply to running runs at once.", a bordered list (`rounded-lg border`) with one row per registered server in name order: checkbox, name (500), "Private network" badge, URL in `text-muted` below; then the primary button "Save MCP servers" (phone: in the sticky footer). Its own form posts to `/projects/{key}/mcp-servers`.
- Project tab without servers: the dashed empty panel "No MCP servers registered", "An admin registers MCP servers for the whole instance on the MCP servers page; they appear here to enable for this project.", secondary button "Open MCP servers" linking to `/mcp-servers`.
- Phone: the project tab row scrolls horizontally with the active tab in view. The server form is a full-screen sheet: one column, field pairs stacked, body scrolls, "Cancel" and "Create MCP server" in a sticky footer.
- Empty state texts: heading "MCP servers" with count, subtitle "Third-party MCP servers that agents reach through the gateway. The gateway adds the credential; it never enters the sandbox.", title "No MCP servers yet", body "Register an HTTP MCP server with a credential reference, then enable it for a project. Its tools appear in the project's next run.", button "New MCP server" (header and empty state).
