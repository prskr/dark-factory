## Why

`crates/factory-agent/src/tests.rs` has grown to 8,709 lines: about 100 tests of nine different modules in one file, 34 of them named after review rounds (`test_review_r38_…`, `test_finding_21_…`) instead of the behavior they check, and every `run_session` scenario repeats the same 100-line setup. Several production files carry inline test modules that are larger than the code they test. Pre-MVP, with the suites still growing, is the cheapest time to restructure them. Functions have no length limit either: 15 production functions exceed 100 lines, `run_session` alone has 743.

## What Changes

- Split `crates/factory-agent/src/tests.rs` into a `tests/` directory with one file per exercised module (CLI and logging, connection, outbox, git hardening, workspace, harness, transcript, MCP, usage and budgets, runner scenarios) and a shared fixture module.
- Add shared fixtures for the `run_session` scenarios (temp repository, fake-agent `Assign`, `RunDriverParams`, outbound collector) and use them in place of the copied setup blocks.
- Rename the 34 tests named after review rounds or findings after the behavior they check.
- Move inline `#[cfg(test)] mod tests` blocks of more than about 500 lines into `<module>/tests.rs`:
  - `df-agent-channel/src/session.rs` (944 lines of code, 1,202 of tests)
  - `df-k8s/src/provider.rs` (875 / 1,062)
  - `df-db/src/tasks.rs` (772 / 1,061)
  - `df-k8s/src/reconcile.rs` (529 / 858)
  - `df-k8s/src/render.rs` (653 / 662, with its insta snapshots)
  - `df-agent-channel/src/scheduler.rs` (272 / 528)
- Split test files of more than about 1,500 lines by topic: `df-web/src/task_pages/tests.rs` (2,276) and `df-web/src/egress/tests.rs` (1,777).
- Document the convention (inline tests up to about 500 lines, then `<module>/tests.rs`; test files split by topic beyond about 1,500 lines; tests named after behavior) in `AGENTS.md`.
- Enforce `clippy::too_many_lines` (threshold 100, root `clippy.toml`) in `cargo clippy` and in the Bazel lint run of CI. The 15 production functions over the limit today get `#[expect(clippy::too_many_lines, reason = …)]`; test modules opt out at module level. File length has no clippy lint and stays a documented guideline.
- No behavior changes: tests are moved and renamed, with no test removed or weakened. Production code changes only in its `mod tests` declarations and the `#[expect]` attributes of the lint.

Out of scope, recorded as follow-ups in the design:
- `factory-agent/src/runner.rs`: `run_session` is a single 850-line function.
- `dark-factory/src/main.rs`: about 970 lines of code.
- Test files of 1,000 to 1,500 lines (`df-web/src/config_pages/tests.rs`, `df-agent-channel/tests/agent_port.rs`, `df-gateway/src/proxy/tests.rs`).
- `df-k8s/src/crd.rs` (4,750 lines), which is generated by `kopium`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This is a test-code refactor without behavior changes (`skip_specs: true`).

## Impact

- `crates/factory-agent`: `src/tests.rs` becomes `src/tests/` (`mod.rs` plus topic files); `src/main.rs` keeps `mod tests;`. `idle_tests.rs` moves into the new directory.
- `crates/df-agent-channel`: `src/session.rs`, `src/scheduler.rs`, new `src/session/tests.rs`, `src/scheduler/tests.rs`.
- `crates/df-k8s`: `src/provider.rs`, `src/reconcile.rs`, `src/render.rs`, new `tests.rs` files, `src/snapshots/` moves to `src/render/snapshots/`, and `BUILD.bazel` (`data` glob of the test target).
- `crates/df-db`: `src/tasks.rs`, new `src/tasks/tests.rs`.
- `crates/df-web`: `src/task_pages/tests.rs` and `src/egress/tests.rs` become directories.
- `AGENTS.md`: test organization rules and the function length limit.
- Lint configuration: new `clippy.toml`, `[workspace.lints.clippy]` in the root `Cargo.toml`, `[lints.clippy]` of `plugins/forgejo` and `plugins/test-probe`, `build:lint` in `.bazelrc`, `exports_files` in the root `BUILD.bazel`.
- The 15 production functions over 100 lines get an `#[expect]` (listed in design D7); their code does not change.
- No dependency, API, schema or runtime configuration changes. Coverage must stay the same.
