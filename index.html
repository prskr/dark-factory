Get started

Tasks and chats

Describe a task, pick a persona and follow the live transcript. Send follow-up messages and answer questions from your phone.

Sandboxed runs

Every run gets its own Kubernetes pod, in a Kata Containers microVM where available. A small Rust runtime runs Claude Code or another ACP harness.

Controlled network access

Sandboxes reach only a gateway with host allowlists. A live view shows every connection, and a blocked host is one click from a rule.

Git is the only state

Agents clone, commit and push in their own workspace. Dark Factory opens the draft pull request; review stays in your forge.

Forges as plugins

Forgejo and GitHub integrations are sandboxed WebAssembly components. A new forge does not change the control plane.

Lean by design

A compiled control plane and runtime, one PostgreSQL database per instance, no shared tenancy. Cheap enough to run several instances.

Pre-MVP

Dark Factory has no stable release line and no production installation yet. Versions are named YYYY.M.N, and every release may change configuration, the database schema or the web UI incompatibly. Features that are designed but not built are marked as planned in the README.

Who it is for

  • You run Kubernetes yourself, with Kata Containers, cert-manager and a CNI that enforces network policies.
  • You have your own Git forge (Forgejo or GitHub) and an OIDC provider such as Keycloak.
  • You want agents to use a Claude subscription instead of API pricing.
  • You are fine with an early project and willing to read the docs and the source.

Who it is not for

  • No Kubernetes: Dark Factory runs only on Kubernetes. There are no SSH or cloud runtimes and no plan for them.
  • No Kata Containers: without a microVM runtime, sandboxes share the node kernel. That works, but the isolation is weaker than the design intends.
  • Multi-tenant needs: one instance and one database belong to one tenant. There is no SaaS mode and none is planned.
  • Stability needs: until the first stable version, expect incompatible changes between releases and no migration guarantees.
  • Code review in a UI: review happens in your forge on the pull request, not in Dark Factory.
